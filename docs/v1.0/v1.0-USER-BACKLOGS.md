## Detailed User Stories

### US-01: Secure Role-Based Login

**As a** User (All Roles),
**I want to** log in securely with my role,
**so that** my personal data and access are protected.

**Acceptance Criteria:**
- [x] Email/password authentication via Better Auth
- [x] Session-based auth stored in database
- [x] Role determines visible navigation and accessible features
- [x] Banned users blocked at session creation
- [x] Guest users redirected to standalone guest layout

**Implementation:** `/app/(auth)/sign-in`, `lib/auth.ts`, `lib/auth-helpers.ts`

---

### US-02: User Account Management

**As an** Administrator,
**I want to** create and manage accounts for all users,
**so that** I can control system access and maintain security.

**Acceptance Criteria:**
- [x] Create user with name, email, password, role, and faculty assignment
- [x] Edit existing user details (role, faculty, name)
- [x] Ban and reactivate user accounts
- [x] View user list with search and role filtering
- [x] Dashboard shows user statistics (total, active, by role)

**Implementation:** `/app/(portal)/admin/users`, `/api/admin/users`, `/api/admin/create-user`, `/api/admin/users/stats`

---

### US-03: Terms and Conditions Agreement

**As a** Student,
**I want to** agree to the Terms and Conditions,
**so that** I can legally proceed with my article submission.

**Acceptance Criteria:**
- [x] T&C checkbox must be checked before submission is allowed
- [x] Submission blocked (validation error) if `agreed` is false
- [x] Agreement state (`agreed` boolean) stored on submission record

**Implementation:** `/app/(portal)/student/submissions`, `/api/submissions` (POST/PUT)

---

### US-04: Upload Word Documents and Images

**As a** Student,
**I want to** upload Word documents and images,
**so that** I can submit my work for the university magazine.

**Acceptance Criteria:**
- [x] Upload .doc, .docx files and image files (PNG, JPG, GIF, WEBP, SVG)
- [x] Files stored in Vercel Blob with metadata in SubmissionFile table
- [x] File type validation enforced server-side based on admin configuration
- [x] File size validation enforced based on admin-configured limits
- [x] Files can be deleted from draft submissions

**Implementation:** `/api/submissions/upload`, `/api/submissions/files`, `@vercel/blob`

---

### US-05: Save Draft Submissions

**As a** Student,
**I want to** save a draft of my submission,
**so that** I can complete or edit it later before final submission.

**Acceptance Criteria:**
- [x] New submissions start with DRAFT status
- [x] Students can save title, files, and notes without submitting
- [x] Multiple drafts allowed per student
- [x] Drafts visible in student's submissions list with DRAFT badge

**Implementation:** `/api/submissions` (POST with status=DRAFT)

---

### US-06: Edit Submissions Before Final Closure

**As a** Student,
**I want to** edit my contribution before the final closure date,
**so that** I can improve my work based on feedback.

**Acceptance Criteria:**
- [x] Students can edit title, notes, and files on existing submissions
- [x] Edits allowed until the final closure date
- [x] 403 error returned after final closure date
- [x] Students can still edit after first closure (but cannot create new)

**Implementation:** `/api/submissions` (PUT), `lib/closure-guard.ts`

---

### US-07: Set Closure and Final Closure Dates

**As an** Administrator,
**I want to** set the Closure and Final Closure dates,
**so that** the system stops accepting new entries automatically.

**Acceptance Criteria:**
- [x] Admin sets first closure date (blocks new submissions)
- [x] Admin sets final closure date (blocks all mutations)
- [x] Only one academic year can be active at a time
- [x] Only current/future years can be activated
- [x] Closure dates enforced via server-side guards on all mutation routes

**Implementation:** `/app/(portal)/admin/closure-dates`, `/api/admin/academic-years`, `lib/closure-guard.ts`

---

### US-08: Configure File Upload Limits

**As an** Administrator,
**I want to** configure file upload (file size, count) limits,
**so that** the system remains stable.

**Acceptance Criteria:**
- [x] Configure max file size (in MB)
- [x] Configure max files per submission
- [x] Configure allowed file types (extensions)
- [x] Toggle uploads on/off entirely
- [x] Limits enforced server-side during upload
- [x] Settings stored in ConfigSetting table

**Implementation:** `/app/(portal)/admin/upload-rules`, `/api/admin/upload-rules`, `/api/config/upload-rules`

---

### US-09: View Own Faculty Submissions

**As a** Marketing Coordinator,
**I want to** view submissions from my own Faculty only,
**so that** I can manage them efficiently.

**Acceptance Criteria:**
- [x] Only SUBMITTED submissions shown (not drafts)
- [x] Scoped to coordinator's assigned faculty
- [x] Active academic year only (no year switcher)
- [x] Filter by: All / Selected Only / Not Selected
- [x] Sort by: Newest / Oldest / Selected First
- [x] Submission count badge displayed

**Implementation:** `/app/(portal)/coordinator/submissions`, `/api/coordinator/submissions`

---

### US-10: Coordinator Comments on Submissions

**As a** Marketing Coordinator,
**I want to** add comments to a student's submission,
**so that** they receive feedback within 14 days.

**Acceptance Criteria:**
- [x] Coordinator can add comments on submissions from their faculty
- [x] Comments visible to both coordinator and student
- [x] Comment thread with nested replies
- [x] Comments blocked after final closure date
- [x] Adding a comment auto-sets review status to COMMENTED

**Implementation:** `/api/comments` (POST), `/api/coordinator/submissions/[id]` (reviewStatus)

---

### US-11: Student Comments on Own Submissions

**As a** Student,
**I want to** add comments to my own submission,
**so that** I can provide additional notes or clarifications to the Coordinator.

**Acceptance Criteria:**
- [x] Students can reply to existing coordinator comments (reply-only)
- [x] Students cannot start new comment threads
- [x] Replies show student name and role badge
- [x] Comments blocked after final closure date

**Implementation:** `/api/comments` (POST with parentId required for students)

---

### US-12: Select Contributions for Publication

**As a** Marketing Coordinator,
**I want to** select specific contributions,
**so that** they can be finalized for publication.

**Acceptance Criteria:**
- [x] Toggle "Selected for Publication" on submission detail
- [x] Confirmation modal before selection/deselection
- [x] Selected submissions visible to Manager and Guest
- [x] Selection state persisted (`isSelected`, `selectedAt`, `selectedById`)
- [x] Email notification sent to student when selected
- [x] Selection blocked after final closure date

**Implementation:** `/api/coordinator/submissions/[id]` (PATCH), `/app/(portal)/coordinator/submissions`

---

### US-13: Automated Email Notifications

**As a** User (Student/Coordinator),
**I want to** receive automated email notifications,
**so that** I am alerted about successful submissions or new comments.

**Acceptance Criteria:**
- [x] Coordinator receives email when a student in their faculty submits
- [x] Student receives email when their submission is selected for publication
- [x] Emails sent via Nodemailer (Gmail SMTP) in fire-and-forget mode
- [x] Email failure does not block the triggering action

**Implementation:** `lib/mailer.ts`, `/api/submissions` (on submit), `/api/coordinator/submissions/[id]` (on select)

---

### US-14: Statistical Dashboards and Charts

**As a** Marketing Coordinator/Manager,
**I want to** view statistical charts and dashboards,
**so that** I can monitor participation levels per Faculty.

**Acceptance Criteria:**
- [x] Statistics tab with submission counts, contributor counts, and percentages per faculty
- [x] Manager/Admin see all faculties in sortable table
- [x] Coordinator/Guest see single-faculty card view
- [x] Year selector for Manager/Admin
- [x] Summary cards (Total Submissions, Contributors, Faculties)
- [x] Role-based dashboards with stat cards, recent items, and quick actions

**Implementation:** `/app/(portal)/reports`, `/api/reports`, `/app/(portal)/page.tsx` (dashboards)

---

### US-15: Submissions Awaiting Comments

**As a** Marketing Coordinator,
**I want to** see a list of submissions awaiting comments,
**so that** 14-day deadlines are not missed.

**Acceptance Criteria:**
- [x] Exceptions tab in reports shows submissions with no coordinator comment
- [x] Overdue toggle filters submissions >14 days without comment
- [x] Exception detail slide-over with waiting days calculation
- [x] Coordinator sees only their faculty's exceptions
- [x] Waiting label contextual: "Waiting for Comment" (active year) / "Waited for Comment" (past year)

**Implementation:** `/api/reports` (type=exceptions), `/app/(portal)/reports` (Exceptions tab)

---

### US-16: Review Status Tracking

**As the** system,
**set** default status as "Pending". When the coordinator downloads a student contribution file, update the status to "Reviewing". Set the status to "Commented" after the coordinator comments on the contribution.

**Acceptance Criteria:**
- [x] New submissions default to `PENDING` review status
- [x] Status transitions to `REVIEWING` when coordinator opens/downloads files
- [x] Status auto-transitions to `COMMENTED` when coordinator adds a comment
- [x] Transitions are forward-only (PENDING → REVIEWING → COMMENTED, never backward)
- [x] Review status badge visible on coordinator submission detail

**Implementation:** `ReviewStatus` enum, `/api/coordinator/submissions/[id]` (PATCH), `/api/comments` (auto-set on comment)

---

### US-17: Download Selected Contributions as ZIP

**As a** Marketing Manager,
**I want to** download selected contributions as a ZIP file,
**so that** I can send them to the printing department.

**Acceptance Criteria:**
- [x] Download ZIP button per academic year section
- [x] ZIP contains files organized as: `Faculty Name / Student Name / filename`
- [x] Streaming ZIP generation (memory-efficient with archiver)
- [x] ZIP filename includes academic year label

**Implementation:** `/api/manager/submissions/download`, `/app/(portal)/manager/submissions`

---

### US-18: Export Reports as PDF or Excel

**As a** Marketing Manager/Coordinator,
**I want to** export reports as PDF or Excel,
**so that** data can be shared externally.

**Acceptance Criteria:**
- [x] Export dropdown with PDF and Excel options
- [x] PDF: landscape A4 with title, generated date, and formatted table
- [x] Excel: .xlsx file with sheet name and headers
- [x] Both generated client-side (no server round-trip)
- [x] Available for both Statistics and Exceptions tabs

**Implementation:** `lib/export-report.ts`, `/app/(portal)/reports`

---

### US-20: Faculty-Scoped Guest Access

**As a** Guest,
**I want to** log in using my Faculty's specific guest account,
**so that** I can view the selected reports of only that faculty.

**Acceptance Criteria:**
- [x] Guest login scoped to assigned faculty
- [x] Only selected submissions visible (not all submitted)
- [x] Standalone layout with no sidebar (separate from portal)
- [x] Year selector to browse past years (only years with selected submissions)
- [x] Summary stats: total submissions, percentage of university total, distinct contributors
- [x] Read-only access — no editing, commenting, or selecting

**Implementation:** `/app/(guest)/guest`, `/api/guest/submissions`
