# Test Cases — v1.0 MVP

> Comprehensive test cases for verifying all user workflows in the University Magazine Contribution System.

**Test Environment:** [Demo Link](https://university-magazine-system-git-development-uni-que-url.vercel.app)

**Default Password:** `password` (all seeded accounts)

> **Note on Email Testing:** To test email notifications (TC-COORD-12, TC-COORD-13), the tester must create accounts using **real email addresses** they can access. Seeded accounts use fake `@uog.com` emails that cannot receive mail. Use the Admin panel (`/admin/users`) to create a new coordinator/student with your real Gmail/email, assign them to a faculty, then trigger the notification flow.

## 9. Cross-Role Scenarios

### TC-CROSS-01: Submission Lifecycle

1. **Student** creates draft → uploads files → submits
2. **Coordinator** receives email → opens submission → review status changes to REVIEWING
3. **Coordinator** adds comment → review status auto-changes to COMMENTED
4. **Student** replies to comment
5. **Coordinator** selects for publication → student receives email
6. **Manager** sees selected submission → downloads ZIP
7. **Guest** sees selected submission in read-only view
8. **Reports** show updated statistics

### TC-CROSS-02: Exception Report Accuracy

1. **Student** submits a contribution
2. **Coordinator** does NOT comment (wait >14 days)
3. **Manager** views Reports → Exceptions tab
4. **Expected:** Submission appears as "Overdue" exception with correct waiting days

### TC-CROSS-03: Faculty Isolation

1. **Coordinator A** (Engineering) tries to access Science submissions
2. **Guest A** (Engineering) tries to access Business submissions
3. **Expected:** Both get empty results or 403. Faculty isolation enforced.

### TC-CROSS-04: Closure Date Enforcement

1. **Admin** sets first closure date to yesterday
2. **Student** tries to create new submission → Blocked (403)
3. **Student** tries to edit existing draft → Still allowed
4. **Admin** sets final closure date to yesterday
5. **Student** tries to edit anything → Blocked (403)
6. **Coordinator** tries to add comment → Blocked (403)

### TC-CROSS-05: Review Status Lifecycle

1. **Student** submits → review status is `PENDING`
2. **Coordinator** opens/downloads files → status transitions to `REVIEWING`
3. **Coordinator** adds comment → status auto-transitions to `COMMENTED`
4. **Expected:** Status never goes backward

### TC-CROSS-06: Guest Year Navigation

1. **Admin** ensures selected submissions exist across multiple years
2. **Guest** logs in → sees current year's selected articles
3. **Guest** switches year via dropdown → sees past year's selected articles
4. **Expected:** Summary stats update per-year, article list changes

### TC-CROSS-07: Upload Rules Enforcement

1. **Admin** sets max file size to 1 MB and allowed types to DOC only
2. **Student** tries to upload a 2 MB file → Rejected
3. **Student** tries to upload a PNG → Rejected
4. **Student** uploads a 500 KB .doc file → Accepted

## 10. Edge Cases

### TC-EDGE-01: Empty Faculty

- **Steps:** Create a new faculty with no students or submissions → View reports
- **Expected:** Faculty appears in stats with 0 submissions, 0 contributors, 0%.

### TC-EDGE-02: Student with No Faculty

- **Steps:** Attempt API calls without faculty assignment
- **Expected:** Appropriate error handling. No crashes.

### TC-EDGE-03: Large File Upload

- **Steps:** Upload a file near the max allowed size
- **Expected:** Upload succeeds if within limits. Error if exceeds.

### TC-EDGE-04: Concurrent Selection Toggle

- **Steps:** Two coordinators try to toggle selection on same submission simultaneously
- **Expected:** Last write wins. No data corruption.

### TC-EDGE-05: Long Comment Thread

- **Steps:** Create 20+ comments on a single submission
- **Expected:** Thread remains scrollable. Performance acceptable.

### TC-EDGE-06: Guest with No Selected Submissions

- **Steps:** Guest logs in for a faculty with no selected submissions for any year
- **Expected:** Empty state displayed. Year dropdown empty or not shown.

### TC-EDGE-07: Multiple Submissions per Student

- **Steps:** Student creates 5+ submissions (mix of draft and submitted)
- **Expected:** All submissions visible in list. Counts on dashboard accurate.

### TC-EDGE-08: Academic Year with No Submissions

- **Steps:** Admin creates and activates a year → Check reports before any student submits
- **Expected:** Reports show 0 across all faculties. No errors.

### TC-EDGE-09: Rapid Comment Posting

- **Steps:** Post multiple comments in quick succession on the same submission
- **Expected:** All comments saved correctly. No duplicates or lost data.

### TC-EDGE-10: Export Empty Report

- **Steps:** Navigate to reports for an academic year with no data → Export as PDF/Excel
- **Expected:** File downloads with headers but empty data rows. No crash.
