```
       │  └──────────────────┘  └──────────────────┘
       │
       │  ┌──────────────────┐  ┌──────────────────┐
       └──│  Session         │  │  ConfigSetting   │
          │  (Better Auth)   │  │  (upload rules)  │
          └──────────────────┘  └──────────────────┘
```

**Models:** User, Session, Account, Verification, Faculty, AcademicYear, Submission, SubmissionFile, SubmissionComment, ConfigSetting

**Enums:**
- `Role` — ADMINISTRATOR, MARKETING_MANAGER, MARKETING_COORDINATOR, STUDENT, GUEST
- `SubmissionStatus` — DRAFT, SUBMITTED
- `ReviewStatus` — PENDING, REVIEWING, COMMENTED

**Key relationships:**
- User belongs to one Faculty
- Submission belongs to User (author), AcademicYear, and optionally selected by User (coordinator)
- SubmissionFile and SubmissionComment belong to Submission
- SubmissionComment has self-referential parent/replies for nested threads

**Review status transitions:**
- Default: `PENDING`
- When coordinator downloads/opens a file: `REVIEWING` (forward-only via PATCH)
- When coordinator adds a comment: `COMMENTED` (auto-set by comments API)
- Transitions are forward-only (PENDING → REVIEWING → COMMENTED, never backward)

## Authentication & Authorization

### Better Auth Setup

```
                      ┌─────────────────┐
                      │   Better Auth   │
                      │   (Server)      │
                      ├─────────────────┤
                      │ Email/Password  │
                      │ Session-based   │
                      │ Admin plugin    │
                      │ Database hooks  │
                      └────────┬────────┘
                               │
                ┌──────────────┼──────────────┐
                ▼              ▼              ▼
         ┌───────────┐  ┌───────────┐  ┌───────────┐
         │ API Route │  │ Server    │  │ Client    │
         │ Handler   │  │ Component │  │ Component │
         └───────────┘  └───────────┘  └───────────┘
         getSession()   getCurrentUser() useSession()
```

**5 roles with scoped access:**

| Role | Scope | Access |
|------|-------|--------|
| ADMINISTRATOR | System-wide | Manage years, users, upload rules, reports, dashboard stats |
| STUDENT | Own submissions | Create, edit, submit, comment (reply-only), dashboard |
| MARKETING_COORDINATOR | Own faculty, active year | Review, comment, select submissions, update review status, reports |
| MARKETING_MANAGER | All faculties, all years | View submissions, download ZIP, reports, export PDF/Excel |
| GUEST | Own faculty, selected only | Read-only view of selected articles, summary stats, year selector |

**Auth flow:**
1. Sign-in via `/api/auth/[...all]` (Better Auth catch-all)
2. Session stored in database (`session` table)
3. Each API route calls `auth.api.getSession({ headers })` to authenticate
4. Role checked inline — no middleware; each route enforces its own permissions
5. Banned users blocked at session creation via `databaseHooks.session.create.before`
6. Guest users redirected from portal layout to `/guest` route group

## API Route Architecture

All routes are Next.js App Router API handlers (`route.ts` files). Authentication and role checks are performed at the top of each handler.

```

├── auth/[...all]/route.ts            # Better Auth catch-all handler
├── academic-years/route.ts           # GET: public year data
├── faculties/route.ts                # GET: faculty list
├── submissions/
│   ├── route.ts                      # GET/POST/PUT/DELETE (student CRUD)
│   ├── upload/route.ts               # POST: Vercel Blob client upload (handleUpload)
│   └── files/route.ts                # POST/DELETE: submission file metadata
├── comments/route.ts                 # GET/POST: comment threads
├── coordinator/
│   └── submissions/

├── manager/

├── guest/

```

## Closure Date Enforcement

The system enforces two deadlines per academic year that gate mutations:

```
  ──────────────────────────────────────────────────────────▶ Time
  │                        │                      │
  │   Open Period          │  Partial Closure      │  Full Closure
  │                        │                      │
  │  Students: create,     │  Students: edit,     │  All: read-only
  │  edit, submit, comment │  comment (no new)    │
  │  Coordinators: review, │  Coordinators: same  │
  │  comment, select       │                      │
  │                        │                      │
  ▼                        ▼                      ▼
  Year Activated     First Closure Date     Final Closure Date
```

**Implementation** (`lib/closure-guard.ts`):
- `getActiveAcademicYear()` — fetches the active year with closure dates
- `isPastFirstClosure()` — blocks new submission creation
- `isPastFinalClosure()` — blocks all mutations (edits, comments, file changes)

Guards are called at the top of mutation routes and return `403` if the deadline has passed.

## File Storage

**Provider:** Vercel Blob (cloud object storage)

```
Student Upload → Vercel Blob Client Upload → Returns URL
                  (handleUpload API)               │
                                                   ▼
                                         POST /api/submissions/files
                                         (save metadata to DB)
                                                   │
                                                   ▼
                                         SubmissionFile record
                                         (url, pathname, contentType, size)
                                                   │
                                                   ▼
                                Manager Download → Fetch URLs → Stream into ZIP
```

- Files uploaded via `@vercel/blob` client upload with `handleUpload()` in `/api/submissions/upload`
- File metadata saved separately via `POST /api/submissions/files`
- File deletion via `DELETE /api/submissions/files`
- Configurable limits via `ConfigSetting` (max size, allowed types, max files per submission)
- Manager ZIP download uses `archiver` to stream files into `Faculty/Student/filename` structure

## Email Notifications

**Provider:** Nodemailer with Gmail SMTP (configurable)

**Triggers:**
1. **Student submits:** When a student submits a submission (status → SUBMITTED), a fire-and-forget email is sent to the faculty's coordinator
2. **Coordinator selects:** When a coordinator selects a submission for publication, an email is sent to the student

```
Student Submits  → API Route → sendMail() → SMTP → Coordinator Inbox
Coordinator Selects → API Route → sendMail() → SMTP → Student Inbox
                                     │
                                 (non-blocking,
                                  .catch(console.error))
```

**Configuration** (environment variables):
- `SMTP_HOST` — SMTP server (e.g., `smtp.gmail.com`)
- `SMTP_PORT` — Port (587 for TLS, 465 for SSL)
- `SMTP_USER` — Email account username
- `SMTP_PASS` — App password (not account password)
- `SMTP_FROM` — Sender address

## Report Exports

Reports can be exported from the reports page as PDF or Excel:

```
Reports Page → Export Dropdown → exportToPdf() / exportToExcel()
                                       │
                                       ▼
                              Client-side generation
                              (jsPDF / SheetJS xlsx)
                                       │
                                       ▼
                              Browser download trigger
```

- **PDF:** jsPDF with jspdf-autotable for formatted tables (landscape A4, title, date, styled headers)
- **Excel:** SheetJS xlsx for spreadsheet generation
- Both exports run entirely client-side — no server round-trip

## Security Model

| Layer | Protection |
|-------|-----------|
| Authentication | Better Auth session-based with email/password |
| Authorization | Role check at every API route — no global middleware |
| Faculty isolation | Coordinators and guests scoped to their assigned faculty |
| Guest isolation | Separate route group with dedicated layout; redirected from portal |
| Closure enforcement | Deadline guards block mutations after closure dates |
| Review status | Forward-only transitions prevent status regression |
| User bans | Blocked at session creation, preventing sign-in |
| File validation | Configurable upload rules (size, type, count); enforced server-side |
| Input validation | Zod schemas on form inputs; Prisma parameterized queries |
| CSRF | Better Auth built-in CSRF protection via session tokens |

## Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| Route-level auth (no middleware) | Simpler mental model; each route is self-contained and testable |
| Prisma with native pg adapter | Required for Neon serverless PostgreSQL on Vercel |
| Better Auth over NextAuth | Built-in admin/role plugin, simpler API, better TypeScript DX |
| SWR over React Query | Lighter weight, sufficient for the app's data fetching needs |
| Vercel Blob over S3 | Native Vercel integration, zero-config, works with serverless |
| Streaming ZIP (Archiver) | Memory-efficient for large downloads; no temp file on disk |
| Fire-and-forget email | Submission response isn't blocked by email delivery |
| Academic year scoping | Submissions tied to year at creation; historical data preserved |
| Separate guest route group | Guests get a minimal UI without sidebar; clearer separation of concerns |
| Client-side report export | PDF/Excel generated in browser; no server load for export |
| Forward-only review status | Prevents accidental status regression; auto-set by comment API |
| Client upload with handleUpload | Vercel Blob client upload pattern; server validates but doesn't stream file |
