## Detailed User Stories

### US-21: First Login Password Change

**As an** admin-created user (All Roles),
**I want to** be forced to change my temporary password on first login,
**so that** my account is secured with a password only I know.

**Acceptance Criteria:**
- [x] Users with `mustChangePassword=true` are redirected to `/change-password`
- [x] User cannot access any page until the password has been changed
- [x] Gate enforced in portal layout, guest layout, and API helper
- [x] After successful password change, `mustChangePassword` is set to `false`

**Implementation:** `/app/(auth)/change-password`, portal layout guard, guest layout guard, `lib/auth-helpers.ts`

---

### US-22: Login Activity Welcome

**As a** User (All Roles),
**I want to** see when I last logged in after signing in,
**so that** I can detect unauthorized access to my account.

**Acceptance Criteria:**
- [x] Welcome card on dashboard shows last login timestamp
- [x] First-time login displays a "first login" message instead of a timestamp
- [x] Timestamp recorded on session creation only (not on page load)

**Implementation:** `/app/(portal)/page.tsx` (dashboard welcome card), session creation hook

---

### US-23: Audit Trail for Selection Changes

**As the** system (System/Admin),
**I want** all coordinator selection/deselection actions recorded in an immutable audit log,
**so that** there is accountability for publication decisions.

**Acceptance Criteria:**
- [x] AuditLog entry created on every select/deselect action
- [x] Entries are append-only (no edit or delete operations permitted)
- [x] Each record captures: actor, timestamp, submission, old value, and new value

**Implementation:** `AuditLog` model, `/api/coordinator/submissions/[id]` (PATCH — audit log write on selection toggle)

---

### US-24: Admin Audit Log Viewer

**As an** Administrator,
**I want to** view the audit log with filtering and pagination,
**so that** I can review selection history efficiently.

**Acceptance Criteria:**
- [x] Paginated audit log page at `/admin/audit`
- [x] Date filter presets: 7 days, 30 days, all time
- [x] Custom date range filter
- [x] Each entry shows actor name, action, submission details, and timestamp

**Implementation:** `/app/(portal)/admin/audit`, `/api/admin/audit`

---

### US-25: Guest Self-Registration

**As an** external user (Guest/Public),
**I want to** register as a guest for a specific faculty,
**so that** I can view selected publications without needing an admin to create my account.

**Acceptance Criteria:**
- [x] Public registration form at `/register`
- [x] User provides name, email, password, and faculty selection
- [x] GUEST role assigned server-side (not user-selectable)
- [x] Account is immediately active after registration

**Implementation:** `/app/(auth)/register`, `/api/auth/register`

---

### US-26: Coordinator Guest Notification

**As a** Marketing Coordinator,
**I want to** receive an email when a new guest registers for my faculty,
**so that** I am aware of who is viewing published work.

**Acceptance Criteria:**
- [x] Email sent to faculty coordinator(s) upon guest registration
- [x] Email delivery is fire-and-forget (non-blocking to the registration flow)

**Implementation:** `lib/mailer.ts` (guest registration notification), `/api/auth/register`

---

### US-27: Coordinator Guest List

**As a** Marketing Coordinator,
**I want to** view a list of guests registered for my faculty,
**so that** I know who has access to view selected contributions.

**Acceptance Criteria:**
- [x] Read-only guest list page scoped to the coordinator's faculty
- [x] Displays guest name, email, and registration date
- [x] Pagination and search supported

**Implementation:** `/app/(portal)/coordinator/guests`, `/api/coordinator/guests`

---

### US-28: Admin Analytics Dashboard

**As an** Administrator,
**I want to** see platform usage statistics with charts,
**so that** I can understand user engagement patterns.

**Acceptance Criteria:**
- [x] Active user counts displayed for 7-day and 30-day windows
- [x] Cumulative active users shown as an AreaChart
- [x] Browser usage distribution shown as a PieChart
- [x] All analytics derived from session data

**Implementation:** `/app/(portal)/admin/analytics`, `/api/admin/analytics`
