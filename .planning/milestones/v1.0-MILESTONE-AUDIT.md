## Tech Debt Summary

### Integration Warnings (2)

**Warning 1: UX-02 — Coordinator filter/sort over page slice only**
- File: `app/(management)/coordinator/submissions/page.tsx`, lines 361–377, 435
- Issue: `filteredSubmissions` derived from `submissions` (page slice, max `pageSize` items). Coordinator filtering "Selected Only" sees only selected items in current page window, not all selected items in faculty. "Showing X of Y" uses `submissions.length` (slice) as denominator rather than `total` (server count). Filter change does not call `setPage(1)`.
- Impact: UX confusion when filtering on multi-page datasets. Not a security or data issue.
- Resolution: Move filter/sort to server-side query params, or add `setPage(1)` on filter change and correct the badge denominator.

**Warning 2: UPLOAD-03 — Hardcoded file type Badges in student dialog header**
- File: `app/(student)/submissions/page.tsx`, lines 781–786
- Issue: Two decorative `<Badge>` components display hardcoded ".doc / .docx" and "PNG / JPG / GIF / SVG" regardless of admin-configured `allowed_file_types`.
- Impact: Visual label may be misleading if admin restricts types. Actual validation (API-level, `accept` attr, `validateFiles`) is correctly config-driven — no file accepted outside the rules.
- Resolution: Derive Badge content from `allowedExts` state variable (already available at this point in the component).
