  <name>Task 1: Create lib/closure-guard.ts</name>
  <files>lib/closure-guard.ts</files>
  <action>
    Create `lib/closure-guard.ts` with three exported functions. The Prisma client now has `firstClosureDate` and `finalClosureDate` on `AcademicYear` (added in Plan 01). The schema uses `isActive: Boolean` to mark the single active year.

    **Implementation requirements:**

    **`getActiveAcademicYear()`**
    - Query: `prisma.academicYear.findFirst({ where: { isActive: true }, select: { id, yearLabel, firstClosureDate, finalClosureDate } })`
    - Returns the active year or `null` if none is active
    - Used by the other two functions and by Phase 3+ routes that need the academicYearId for new submissions

    **`isPastFirstClosure()`**
    - Calls `getActiveAcademicYear()`
    - Returns `false` if: no active year, or active year has `firstClosureDate = null`
    - If `firstClosureDate` is set: create a cutoff = new Date(year.firstClosureDate), then call `cutoff.setHours(23, 59, 59, 999)` to treat the closure date as end-of-day (avoids midnight UTC boundary issue for users in eastern timezones)
    - Return `Date.now() > cutoff.getTime()`
    - Rationale: existing codebase uses this pattern in `app/(student)/submissions/page.tsx` for the same reason

    **`isPastFinalClosure()`**
    - Same pattern as `isPastFirstClosure()` but using `finalClosureDate`
    - Returns `false` if: no active year, or active year has `finalClosureDate = null`

    **Type annotations:**
    - `getActiveAcademicYear()` return type: `Promise<{ id: string; yearLabel: string; firstClosureDate: Date | null; finalClosureDate: Date | null } | null>`
    - `isPastFirstClosure()` and `isPastFinalClosure()` return type: `Promise<boolean>`

    **Import:**
    - `import prisma from "@/lib/prisma";` — use the existing singleton

    Do NOT add caching, do NOT use date-fns (native Date comparison is sufficient per research), do NOT add any parameters — these functions query the DB directly.

    The complete file should be ~40-50 lines.
