  <action>
    **Step 1 — Install the package:**

    ```bash
    cd /home/alfie/next-prisma
    pnpm add nodemailer@^6.9
    pnpm add -D @types/nodemailer
    ```

    CRITICAL: Do NOT install `nodemailer@latest` or `nodemailer@^7` or `nodemailer@^8`. Nodemailer 7+ is ESM-only and will cause `ERR_REQUIRE_ESM` at runtime due to this project's CommonJS/ESM hybrid used by `@prisma/client` and `better-auth`. Pin to `^6.9`.

    Verify after install:
    ```bash
    node -e "const pkg = require('./node_modules/nodemailer/package.json'); console.log(pkg.version)"
    ```
    Confirm the version begins with `6.`.

    **Step 2 — Create `lib/mailer.ts`:**

    Follow the same `globalForPrisma` singleton pattern used in `lib/prisma.ts` (read that file for reference). The module must:

    1. Import nodemailer (CJS default import: `import nodemailer from "nodemailer"`)
    2. Create a module-level singleton transporter using `globalForMailer` pattern — same as `lib/prisma.ts`'s `globalForPrisma`
    3. Configure transporter from env vars:
       - `host: process.env.SMTP_HOST`
       - `port: Number(process.env.SMTP_PORT ?? 587)`
       - `secure: Number(process.env.SMTP_PORT) === 465` (TLS on 465, STARTTLS on 587)
       - `auth: { user: process.env.SMTP_USER, pass: process.env.SMTP_PASS }`
    4. Only assign to `globalForMailer.mailer` in non-production environments (same guard as Prisma singleton)
    5. Export a single `sendMail()` async function with this signature:
       ```typescript
       export async function sendMail(options: {
         to: string | string[];
         subject: string;
         html: string;
         text?: string;
       }): Promise<void>
       ```
    6. Inside `sendMail()`, call `transporter.sendMail()` with:
       - `from: '"University Magazine System" <${process.env.SMTP_FROM}>'`
       - The `to`, `subject`, `html`, `text` from options
    7. `sendMail()` is an async function that throws on error — callers use `.catch(console.error)` for fire-and-forget

    Do NOT add retry logic, do NOT log to database, do NOT await in the caller before responding.

    The correct fire-and-forget call pattern at call sites (for reference — not implemented here):
    ```typescript
    sendMail({ to, subject, html }).catch(console.error);
    return NextResponse.json({ success: true });
    ```
