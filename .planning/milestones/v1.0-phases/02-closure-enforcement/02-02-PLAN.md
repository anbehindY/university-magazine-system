if (await isPastFinalClosure()) {

Guard order in DELETE:
1. Auth check → 401

  <name>Task 2: Add finalClosure gate to onBeforeGenerateToken in upload/route.ts</name>

  <action>
Import `isPastFinalClosure` from `@/lib/closure-guard` at the top of the file.

In the `onBeforeGenerateToken` callback, add the closure check AFTER the session is confirmed available (the session is captured in the outer POST handler scope and is accessible in the closure) but BEFORE the `submissionId` validation and submission ownership check.

The exact insertion point: inside `onBeforeGenerateToken`, after the `submissionId` extraction from `parsedPayload` but before the `if (!submissionId)` throw. Place it as the FIRST substantive check:

```typescript
onBeforeGenerateToken: async (pathname, clientPayload) => {
  const parsedPayload = ...  // existing parsing code — leave unchanged
  const submissionId = parsedPayload?.submissionId;

  // ADD THIS BLOCK:
  if (await isPastFinalClosure()) {
    throw new Error("Submissions are locked. The final closure date has passed.");
  }

  if (!submissionId) {  // existing check — leave unchanged
    throw new Error("Missing submission id.");
  }
  // ... rest of existing code unchanged
```

Use `throw new Error(...)` (not `return NextResponse.json`) because `onBeforeGenerateToken` is a callback inside `handleUpload` — throwing causes `handleUpload` to reject and the outer `POST` handler's `catch` block returns `{ error: message }` with status 400. This is the correct enforcement point per research Pitfall 1.

The session variable is accessible from the outer `POST` closure — no changes needed to session handling.

Do NOT add a guard in `onUploadCompleted` — by that point the blob is already uploaded to Vercel's CDN. The gate must be in `onBeforeGenerateToken` where the token is issued.
