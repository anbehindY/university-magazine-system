### 2. ZIP download works at any time
expected: Click the Download ZIP button as a Marketing Manager — regardless of the finalClosureDate setting. A ZIP file of submissions should download successfully.
result: pass

### 3. Title input is the first form field
expected: Navigate to /submissions as a Student. Open the submission form. The Title input should be the very first user input in the form — appearing after any closure date alerts but before the file upload area.
result: pass

### 4. Title is required on submit
expected: Leave the title field empty and try to submit (not save draft). A toast error "Please enter a title for your submission." should appear and the form should not submit. Saving as draft with empty title should still work fine.
result: pass

### 5. Title not persisted in localStorage
expected: Enter a title, reload the page without saving to the server. The title field should be empty (not restored from localStorage). Other draft fields (notes, agreed, file names) may still restore from localStorage.
result: pass

### 6. Closure date has Info icon and blue styling
expected: View the closure date alert on the student submission form when the closure date has NOT passed. It should display a blue-styled alert (light blue background, blue borders) with an Info icon. When the closure date HAS passed, it should show the red/destructive styling.
result: issue
reported: "Text should say 'Editing is available before [date]'. Yellow styling would be more complementary than blue. Also, title required validation uses HTML5 required attribute showing browser default 'pls fill out this field' — want custom error message from React Hook Form instead."
severity: minor

### 7. Edit mode separates existing and new files
expected: Edit an existing submission that has previously uploaded files. You should see a "Previously uploaded files" section with download/delete options for each file. If you select new files, they appear in a separate "New files to upload" section. No duplication between the two sections.
result: pass

### 8. API validates title on submission
expected: Try to submit a submission via the form with an empty title. The server should reject it with a 400 error "A title is required when submitting." This applies to both new submissions and edits that change status to SUBMITTED. Draft saves with empty title should succeed.
result: issue
reported: "HTML5 required attribute blocks form submission before API validation fires — browser shows 'please fill out this field' instead of custom error. Can't test API validation because browser intercepts first."
severity: minor

### 9. Coordinator email reaches all faculty coordinators
expected: Submit a submission as a Student. Every Marketing Coordinator under that student's faculty should receive a notification email — not just one coordinator, but all of them.
