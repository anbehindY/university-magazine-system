**Sheet setup (per locked decision — slide-over panel):**

- The list stays visible underneath (Sheet uses portal overlay)

**Panel header section (sticky, above comment thread):**
- `<SheetHeader>` with submission title and student name
- `Switch` component (from `components/ui/switch.tsx`) for "Selected for Publication" toggle
  - On change: `fetch(`/api/coordinator/submissions/${id}`, { method: "PATCH", body: JSON.stringify({ isSelected: !current }) })`
  - Optimistically update the local submissions list state
- `Textarea` for notes field (use a standard `<textarea>` with Tailwind classes or the existing `Input` component)
  - Debounce or use a "Save" button — on blur or button click: `fetch(`/api/coordinator/submissions/${id}`, { method: "PATCH", body: JSON.stringify({ notes: value }) })`
  - Show toast via `sonner` on save success/failure

**Comment thread section (scrollable body):**
- Use `useSWR` from the `swr` package installed in Plan 01:
  ```
  const { data: commentsData, mutate } = useSWR(
    selectedSubmissionId ? `/api/comments?submissionId=${selectedSubmissionId}` : null,
    fetcher,
    { refreshInterval: 15000 }
  );
  ```
- Define `fetcher` as `(url: string) => fetch(url).then(r => r.json())`
- Render comments as a vertical list sorted by `createdAt` (API already returns sorted)
- Each comment shows: author name, role badge (e.g., "Coordinator" or "Student"), body text, formatted timestamp
- If comment has `parentId`, indent it slightly or show a "reply to" indicator
- Add a "Reply" link/button on each comment that sets a `replyToId` state variable

**Comment input (bottom of panel):**
- One textarea at the bottom of the thread
- Coordinators can always post (no `parentId` required by API for coordinators)
- When replying (replyToId is set), show "Replying to [author]" indicator with cancel button
- On submit: `fetch("/api/comments", { method: "POST", body: JSON.stringify({ submissionId, content, parentId: replyToId || undefined }) })`
- After successful POST, call `mutate()` to trigger immediate SWR revalidation (comment appears without waiting for 15s poll)
- Clear the textarea and reset replyToId after successful post
- Show toast on error

**Important constraints:**
- Do NOT use `setInterval` for polling — use SWR's `refreshInterval` (locked decision)
- Panel header (toggle + notes) should use `flex-col` with the comment thread in an `overflow-y-auto` container
- Follow existing project conventions: `useState`/`useEffect`, `sonner` toast, Tailwind classes
