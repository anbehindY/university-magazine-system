**POST /api/comments — comment creation (COMM-01, COMM-02, COMM-04)**

Guard order:
1. Auth: `auth.api.getSession({ headers: await headers() })` — 401 if no session
2. Final closure: `isPastFinalClosure()` — 403 "Comments are locked. The final closure date has passed."
3. Body validation: parse `{ submissionId, content, parentId }` from `req.json()`. Require `submissionId` (string) and `content` (non-empty string). `parentId` is optional (nullable). Return 400 if `submissionId` or `content` missing/empty.
4. Fetch submission: `prisma.submission.findUnique({ where: { id: submissionId }, select: { userId: true, facultyId: true } })` — 404 if not found.

Role-based scope enforcement:
- **MARKETING_COORDINATOR path:** Look up coordinator's `facultyId` via `prisma.user.findUnique({ where: { id: session.user.id }, select: { facultyId: true } })`. If `dbUser?.facultyId !== submission.facultyId` — return 403 "Forbidden: cross-faculty access". Coordinator can post with or without `parentId` (top-level or reply).
- **STUDENT path:** Check `submission.userId !== session.user.id` — return 403 "Forbidden: not your submission". **Student MUST provide a non-null `parentId`** — return 400 "Students can only reply to existing comments" if `parentId` is null/undefined. This enforces that coordinators initiate threads per CONTEXT.md.
- **Any other role:** return 403 "Forbidden".

If `parentId` is provided, validate it exists and belongs to the same submission:
```typescript
if (parentId) {
  const parentComment = await prisma.submissionComment.findUnique({
    where: { id: parentId },
    select: { submissionId: true },
  });
  if (!parentComment || parentComment.submissionId !== submissionId) {
    return NextResponse.json({ error: "Parent comment not found on this submission" }, { status: 400 });
  }
}
```

Create the comment:
```typescript
const comment = await prisma.submissionComment.create({
  data: {
    submissionId,
    authorId: session.user.id,
    authorRole: session.user.role,
    body: content,       // API accepts "content", Prisma field is "body"
    parentId: parentId ?? null,
  },
  include: {
    author: { select: { name: true, role: true } },
  },
});
return NextResponse.json({ comment }, { status: 201 });
```

**After the `prisma.submission.update()` call (line ~183) and before the return statement, add:**

```typescript
// COORD-02: Email notification on first SUBMITTED transition
// Fire only when submittedAt was null before (first time) and nextStatus is SUBMITTED
const isFirstSubmission = nextStatus === "SUBMITTED" && existing.submittedAt === null;
if (isFirstSubmission) {
  // Fetch the updated submission's facultyId for coordinator lookup
  const updatedSubmission = await prisma.submission.findUnique({
    where: { id: body.id },
    select: { facultyId: true, title: true },
  });

  if (updatedSubmission?.facultyId) {
    const coordinators = await prisma.user.findMany({
      where: {
        role: "MARKETING_COORDINATOR",
        facultyId: updatedSubmission.facultyId,
      },
      select: { email: true },
    });

    if (coordinators.length > 0) {
      const emails = coordinators.map((c) => c.email);
      const submissionTitle = updatedSubmission.title ?? "Untitled";
      const studentName = session.user.name;
      const appUrl = process.env.NEXT_PUBLIC_APP_URL ?? "http://localhost:3000";

      // Fire-and-forget — do NOT await; errors logged, not thrown
      sendMail({
        to: emails,
        subject: `New submission: ${submissionTitle} — ${studentName}`,
        html: `<p><strong>${studentName}</strong> has submitted a new contribution: <em>${submissionTitle}</em>.</p>
               <p><a href="${appUrl}/coordinator/submissions">View submissions</a></p>`,
        text: `${studentName} has submitted a new contribution: ${submissionTitle}. Visit ${appUrl}/coordinator/submissions to review.`,
      }).catch(console.error);
    }
  }
}
```

**Key details:**
- `existing.submittedAt` is already selected in the `findFirst` call (line ~138) — no additional query needed for the deduplication check.
- `sendMail()` is NOT awaited — fire-and-forget per STATE.md decision. `.catch(console.error)` prevents unhandled promise rejection.
- The email is sent to ALL coordinators in the student's faculty (supports multi-coordinator per COORD-V2-02 at data level).
- `session.user.name` is used for the student name — available from better-auth session.
- `updatedSubmission.title` may be null (existing submissions) — fall back to "Untitled".
- The link target is `/coordinator/submissions` per CONTEXT.md locked decision.
