**Statistical report (type=submissions, RPT-01/02/03):**

Use `prisma.$queryRaw` with `Prisma.sql` template tag for safe parameterization. Import `Prisma` from `@/prisma/generated/client` (NOT `@prisma/client` — project uses custom generated client path).

```typescript
import { Prisma } from "@/prisma/generated/client";

type StatsRow = {
  faculty_id: string;
  submission_count: bigint;
  distinct_contributors: bigint;
};

const whereClause = scopedFacultyId
  ? Prisma.sql`AND s.faculty_id = ${scopedFacultyId}`
  : Prisma.empty;

const yearClause = Prisma.sql`AND s.academic_year_id = ${academicYearId}`;

const rows = await prisma.$queryRaw<StatsRow[]>`
  SELECT
    s.faculty_id,
    COUNT(s.id)              AS submission_count,
    COUNT(DISTINCT s.user_id) AS distinct_contributors
  FROM "Submission" s
  WHERE s.status = 'SUBMITTED'
  ${whereClause}
  ${yearClause}
  GROUP BY s.faculty_id
`;
```

**CRITICAL:** Prisma `$queryRaw` COUNT returns JavaScript `bigint`. Convert with `Number()` before JSON serialization — `JSON.stringify` silently drops BigInt values.

**Faculty name resolution:** `prisma.faculty.findMany({ select: { id: true, name: true } })` into a Map. Same pattern as manager submissions — `Submission.facultyId` has no ORM relation.

**Percentage calculation (RPT-02):** `total = sum of all submission_count`. Each faculty: `percentageOfTotal = (Number(row.submission_count) / total) * 100`, rounded to 1 decimal.

**Response shape:**
```json
{

  "academicYearId": "...",
  "data": [
    {
      "facultyId": "...",
      "facultyName": "...",
      "submissionCount": 12,
      "percentageOfTotal": 40.0,
      "distinctContributors": 8
    }
  ]
}
```

**Exception report query (RPT-04):**

Use Prisma `findMany` with nested `none` filter — NOT `$queryRaw`. This is the correct approach because Prisma supports `comments: { none: { authorRole: "MARKETING_COORDINATOR" } }` natively.

```typescript
const exceptions = await prisma.submission.findMany({
  where: {
    status: "SUBMITTED",
    ...(scopedFacultyId ? { facultyId: scopedFacultyId } : {}),
    ...(academicYearId ? { academicYearId } : {}),
    comments: {
      none: {
        authorRole: "MARKETING_COORDINATOR",
      },
    },
    // RPT-05: add overdue filter when ?overdue=true
    ...(overdue === "true" ? {
      submittedAt: {
        lt: new Date(Date.now() - 14 * 24 * 60 * 60 * 1000),
      },
    } : {}),
  },
  select: {
    id: true,
    title: true,
    submittedAt: true,
    facultyId: true,
    user: { select: { name: true } },
  },
  orderBy: { submittedAt: "asc" },
});
```

**Response mapping:** For each exception row, compute `daysSinceSubmission` from `submittedAt`:
```typescript
const now = Date.now();
const result = exceptions.map(e => ({
  id: e.id,
  title: e.title,
  studentName: e.user.name,
  facultyName: facultyMap.get(e.facultyId ?? "") ?? null,
  submittedAt: e.submittedAt,
  daysSinceSubmission: e.submittedAt
    ? Math.floor((now - e.submittedAt.getTime()) / (24 * 60 * 60 * 1000))
    : null,
}));
```

Use `Math.floor` for daysSinceSubmission — consistent with "more than 14 days ago" meaning 15+ days. Do NOT import date-fns; native Date math is sufficient and consistent with project convention (no date-fns in closure-guard).
