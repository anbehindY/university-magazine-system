**Step 2 — Create GET /api/manager/submissions/route.ts:**

Create the route handler following the coordinator submissions pattern from `app/api/coordinator/submissions/route.ts` but adapted for the manager role:

1. Auth gate: `auth.api.getSession({ headers: await headers() })` — 401 if no session.
2. Role gate: `session.user.role !== "MARKETING_MANAGER"` — return 403 with message "Forbidden. Marketing Manager access required."
3. Parse optional `?facultyId=X` from `req.nextUrl.searchParams`.
4. Query submissions:
   ```
   prisma.submission.findMany({
     where: {
       isSelected: true,
       ...(facultyId ? { facultyId } : {}),
     },
     select: {
       id: true,
       title: true,
       submittedAt: true,
       facultyId: true,
       user: { select: { name: true } },
       _count: { select: { files: true } },
     },
   })
   ```
5. Faculty name resolution: `prisma.faculty.findMany({ select: { id: true, name: true } })` — build a `Map<string, string>` for lookup. Submission.facultyId is a snapshot string with NO ORM relation to Faculty — this separate query + Map pattern is required.
6. Application-layer sort: sort by facultyName ascending (localeCompare), then submittedAt descending within each faculty. Prisma orderBy cannot sort by a resolved name from a snapshot field.
7. Map response to flat shape: `{ id, title, studentName: user.name, facultyName: facultyMap.get(facultyId), submittedAt, fileCount: _count.files }`.
8. Return `NextResponse.json(result)` with 200.
9. Wrap in try/catch — `console.error("Error fetching manager submissions:", error)` and return 500.

Import pattern (follow project conventions):
```typescript
import { auth } from "@/lib/auth";
import prisma from "@/lib/prisma";
import { headers } from "next/headers";
import { NextRequest, NextResponse } from "next/server";
```
