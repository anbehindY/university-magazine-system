    **New SubmissionComment model (add after Submission):**
    ```prisma
    model SubmissionComment {
      id           String     @id @default(uuid())
      submissionId String     @map("submission_id")
      submission   Submission @relation(fields: [submissionId], references: [id], onDelete: Cascade)
      authorId     String     @map("author_id")
      author       User       @relation(fields: [authorId], references: [id])
      authorRole   String     @map("author_role")
      body         String     @db.Text
      createdAt    DateTime   @default(now()) @map("created_at")

      @@index([submissionId])
      @@map("submission_comment")
    }
    ```

    CRITICAL: Do NOT run prisma migrate yet — verify the schema file edits are complete first. Run `npx prisma validate` to confirm the schema is syntactically correct before proceeding to Task 2.

    Note on named relations: Prisma requires bidirectional named relations when two FK relations exist between the same two models. `selectedBy`/`selectedSubmissions` must both use `@relation("SubmissionSelector")`. The existing `user`/`submissions` relation on Submission/User does NOT need a name (it is the only relation for that pair currently). Check whether `Submission` already has a `user User @relation(...)` — if so, the new AcademicYear relation adds a second relation to a new model, which is fine without naming.
