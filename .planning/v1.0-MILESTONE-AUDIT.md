## Integration Check Results

### Cross-Phase Wiring: 22/26 requirements fully wired

### Critical Integration Breaks

**Break 1 — MGR-02: ZIP download closure gate is ABSENT from API route**
- File: `app/api/manager/submissions/download/route.ts`
- Expected: `if (!(await isPastFinalClosure())) return 403`
- Actual: No import of `isPastFinalClosure` or `closure-guard`. No closure check of any kind.
- Impact: Managers can download ZIP at any time, including mid-cycle before final closure.
- Note: Phase 4 VERIFICATION.md claims this is "VERIFIED" and the SUMMARY documents the inverted gate — but the actual committed code does not contain it. **SUMMARY/VERIFICATION diverges from implementation.**

**Break 2 — MGR-02: Manager UI Download button always enabled**
- File: `app/(management)/manager/submissions/page.tsx`, line ~306
- Expected: Button disabled before `finalClosureDate`, wrapped in Tooltip
- Actual: `disabled={downloadingYearId !== null}` — only disabled during active download
- Impact: No UX signal that download is a post-deadline feature

**Break 3 — COORD-02: Submission title field never written by students**
- File: `app/(student)/submissions/page.tsx` — no title input anywhere
- File: `app/api/submissions/route.ts` POST handler — `SubmissionPayload` has no `title`
- Impact: `Submission.title` always null; coordinator email subject always "New submission: Untitled"; coordinator list shows "Untitled" for every submission

**Break 4 — COMM-02/COMM-03: Student comment thread UI does not exist**
- File: `app/(student)/submissions/page.tsx` — no comment thread display, no reply input
- Impact: Students cannot read coordinator comments or post replies from the browser despite API support
